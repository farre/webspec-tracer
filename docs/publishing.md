# Publishing webspec-tracer

Firefox requires extensions to be signed by Mozilla (addons.mozilla.org / AMO).
There are two channels:

- **Unlisted** — Mozilla signs a `.xpi` you distribute yourself (team/personal).
- **Listed** — public on AMO, goes through review.

## Prerequisites

1. An AMO account: https://addons.mozilla.org
2. API credentials: **Developer Hub → Manage API Keys** → generate a JWT
   **issuer** and **secret**.

## Build, package, sign

The manifest is generated by the build; `version` comes from `package.json`
(single source of truth — bump it there for each submission).

```bash
pnpm install
pnpm build                 # → dist/ (+ generated dist/manifest.json)
pnpm package               # → web-ext-artifacts/*.zip (optional sanity check)

export WEB_EXT_API_KEY="user:XXXXXXX:NNN"
export WEB_EXT_API_SECRET="…"

pnpm sign:unlisted         # returns a signed .xpi to host yourself
# or
pnpm sign:listed           # uploads for review; finish listing metadata on AMO
```

Add-on id: `webspec-tracer@farre.se` (in `scripts/manifest.mjs`; permanent once
published). Icon: `assets/icon.svg` (scalable; used for `icons` and the sidebar).

## Source-code submission (reproducible build)

The shipped `dist/*.js` is bundled/minified by esbuild (and vendors `turndown`),
so AMO review needs the source plus build instructions. Provide a source archive:

```bash
git archive --format=zip -o webspec-tracer-src.zip HEAD
```

**Build environment**

- Node 18.x, pnpm 11.x
- `pnpm install` then `pnpm build`
- Output is written to `dist/`, which is exactly what gets packaged/signed.

**What's in the bundle**

- First-party TypeScript under `src/` (compiled by esbuild).
- One third-party runtime dependency, `turndown` (MIT), bundled into the
  background script for HTML→Markdown.
- `assets/w3c_specs.json` — the spec registry, copied verbatim from
  [webspec-index](https://github.com/jnjaeschke/webspec-index) (MIT).
- No remote code is loaded or eval'd; the extension only fetches spec HTML and
  parses it locally with `DOMParser`.

Full source and attribution: see the repository and `THIRD_PARTY_LICENSES.md`
(project is MIT).

## Permissions

Paste this into the AMO review notes if asked to justify permissions.

- `storage`, `unlimitedStorage` — cache parsed specs locally (a single spec's
  parsed content can be large); nothing is sent anywhere.
- `https://bugzilla.mozilla.org/*` — the only user-facing integration: insert a
  generated trace into the bug comment editor at the caret.
- Spec sources, fetched on demand to build the cross-reference graph as a trace
  crosses into a spec:
  - `https://*.spec.whatwg.org/*` — WHATWG living standards (HTML, DOM, URL, Fetch…)
  - `https://tc39.es/*` — TC39 / ECMAScript specs and proposals
  - `https://*.github.io/*` — W3C/WICG/GPUWeb/WebAssembly editor's drafts
  - `https://drafts.csswg.org/*` — CSS Working Group drafts
  - `https://www.w3.org/*`, `https://w3.org/*` — W3C `/TR/` specs and the ReSpec
    spec-generator
  - `https://www.rfc-editor.org/*`, `https://datatracker.ietf.org/*`,
    `https://www.ietf.org/*` — IETF RFCs and drafts

`*.github.io` is broad because editor's drafts for many working groups live
there and the registry resolves specs across them; the extension only issues
GET requests for spec documents. A future hosted index could narrow this.

## Notes

- The extension is Manifest V2 (still accepted by Firefox). The background is
  written side-effect-free so it can move to an MV3 event page later.
- Every submission needs a new `version` in `package.json`.
